# Data loaders and evaluation

User guide: [Data Loading](../../docs/user-guide/data.md). Config: [Configuration](../../docs/user-guide/configuration.md) (`dataset` section).

- **Spatial preprocessing** — `preprocessing.py`: `resize_mode` **`fixed`** (stretch to canvas), **`pad`** (uniform scale so the longer edge equals `max(H, W)` then zero-pad to `target_size`), **`keep_ratio`** (same scale without square pad; then `pad_size_divisor`, MMRotate `RResize`+`Pad`), **`crop`** (native-resolution crop/pad to `target_size`; random crop in training, center crop in val/inference). Used from `oriented_det.runtime.collate` and `oriented_det.runtime.inference`. Training collate then pads the batch to a shared H×W so mixed `keep_ratio` sizes can stack; `odet preds` does not.
- **Training flips** — `flips.py`: `apply_random_train_flips` / `apply_flip_to_image` / `apply_flip_to_rboxes` (MMRotate `RRandomFlip` parity: horizontal / vertical / diagonal at 25% each when all three enabled). Diagonal mirrors centers and **keeps** θ (MMRotate early return); H/V use `norm_angle(π − θ)`. Used from `oriented_det.runtime.collate`.
- **Training random rotate** — `rotates.py`: `apply_random_train_rotate` / `apply_rotate_to_image` / `apply_rotate_to_rboxes` (MMRotate `PolyRandomRotate` range mode, `auto_bound=False`). Image-space sign: PIL CCW uses `geometry.transforms.rotate(-radians)` then `normalize_le90`. Applied after flips in collate. Config: `preprocessing.enable_random_rotate` / `random_rotate_prob` / `random_rotate_angle_range` (degrees). FCOS HRSC 1×/3× and Oriented R-CNN / Faster R-CNN HRSC 3× use p=0.5 ±20°; two-stage 1× and DOTA stay off. Val / inference do not rotate.
- **Photometric augs** — `transforms.py`: `AlbumentationsTransform` / `create_albumentations_augmentation` (color / noise / blur only).
- **mAP** — `evaluation.py`: ``compute_oriented_map`` uses **exact CPU polygon IoU** when ``use_exact_rotated_iou=True`` (Shapely when installed). Set ``evaluation.use_exact_rotated_iou: false`` in training config (or pass ``use_exact_rotated_iou=False``) for GPU sampling IoU during validation — faster, approximate. GT-cover / accuracy on mAP epochs follow the same flag. Final detection NMS is unaffected.
- **GT alignment** — `evaluation.py`: ``compute_gt_best_iou_alignment_metrics`` reports global and per-class **mean best IoU** (each GT’s max rotated IoU vs raw detections on the same image, before score filtering). Emitted by ``odet preds`` / ``make metrics`` as ``gt_alignment_metrics`` in diagnostics and ``analysis_iou*.json``; training logs a per-class table when ``evaluation.extended_gt_metrics`` is true.
- **DOTA** — `dota.py`: `DOTADataset`, `DOTAAnnotation`, loaders. Multi-root tiles: `train_tiles_dirs` / `val_tiles_dirs` in config → `resolve_dota_tile_roots`, `build_dota_split_dataset` (`ConcatDataset`), `collect_dota_image_paths`, **`collect_dota_split_image_paths`**, `dota_label_path_for_image`. Optional **`filter_empty_gt`** (config `dataset.filter_empty_gt`, default `false`) drops tiles with no objects after `difficult_strategy` / class filters — used in **training** and MMRotate parity (`dota_le90_3x.json`). **`make preds` / `make metrics`** enumerate **all** tiles (`filter_empty_gt=False` in `save_predictions.py`). Optional **`dataset.drop_easy_empty_tiles`** (train script, with `tile_metrics_csv`) drops only vacuous empties (`tp=fp=fn=0`) so hard empty+FP tiles can still be oversampled; leave `filter_empty_gt` false.
- **HRSC2016** — `hrsc2016.py`: `HRSC2016Dataset` reads official XML (`mbox_*`, angle in radians) and ImageSets; single class `ship`; le90 via the DOTA polygon path. Config `dataset.format: hrsc2016` with `train_split` / `val_split` (defaults trainval / test). Oriented R-CNN, Faster R-CNN, and FCOS 1×/3× use `keep_ratio` + `pad_size_divisor` 32. FCOS 1×/3× and two-stage 3× enable random rotate p=0.5 ±20°; two-stage 1× leaves rotate off. `odet preds` / `make eval-val` keep the whole-image path (no native sliding windows). Optional DOTA export: `export_hrsc2016_to_dota` / `odet hrsc-to-dota`.
- **Dataset factory** — `build.py`: `build_split_dataset` / `split_class_names` / `collect_split_images` used by `odet train`, `odet stats`, `odet preds`, and related tools.
- **Airbus Playground CSV** — `airbus_playground.py`: `discover_airbus_tiles`, `generate_airbus_playground_csvs` (writes integer **fold** ids; default val fold is **0**), `dated_playground_csv_filenames` / `resolve_playground_csv_filenames` (paired `annotations_YYYYMMDD.csv` + `split_YYYYMMDD.csv` from `tools/generate_airbus_playground_csv.py`), `detect_airbus_split_csv_format`, `apply_airbus_difficult_tags` / `AirbusPlaygroundCSVDataset` (pass `annotations_file`, `split_file`, `val_split_id`, and optional **`difficult_tags`** to match training config; legacy `train`/`val` strings in split CSVs are still accepted). Multi-tag Playground labels are `", ".join(sorted(tags))`; the loader builds `DOTAAnnotation` from structured CSV fields via `DOTAAnnotation.from_corners` (comma in `class_name` is not dropped). **`difficult_tags`** (e.g. `["Partially Hidden"]`) strip those tags, set `difficult=1`, then apply `map_labels` (exact match on the remaining string); use with `difficult_strategy: "ignore"` for don't-care (not lookalike / not `ignore_labels`). Optional **`train_includes_val`** (config `dataset.train_includes_val`, default `false`): when `true`, the train split includes **all** folds (DOTA `train_tiles_dirs` trainval parity); validation still uses `val_split_id` for monitoring only. Optional **`filter_empty_gt`** (config `dataset.filter_empty_gt`) drops tiles with no objects after `map_labels` / `ignore_labels` / `difficult_strategy` — applied to the **train** split only in `tools/train.py` (val keeps all tiles). Don't-care-only and lookalike-only tiles are kept when those annotations remain.
- **`dota_classes.py`** — Canonical DOTA v1.0 class list (`DOTA_V1_CLASSES`, `DOTA_V1_CLASS_SET`) shared with training tools and deploy metadata generation.
